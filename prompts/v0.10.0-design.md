# Increment 10 — AI-Assisted Design Record

**Version:** v0.10.0-design  
**Increment:** Operations Dashboard  
**Requirements:** FR-OP-04, NFR-03  
**Owner:** Zein A. Sunoqrot

## 1. Design Task

Design the Operations Dashboard for the Hotel Reservation System. The dashboard enables an authorized `Hotel Manager` to monitor key operational metrics—occupancy rate, expected arrivals, expected departures, recognized revenue, and real-time room readiness—across a configurable date range.

The design must enforce strict server-side role-based access control (`Hotel Manager` only), define unambiguous date-range and KPI formulas, distinguish earned recognized revenue from unearned advance deposits, and align room readiness counts with the five operational states established in Increment 9.

## 2. AI Assistance

Gemini was used to assist with:

- Defining dashboard KPI formulas, source tables, and server-side RBAC rules (`FR-OP-04`, `NFR-03`).
- Creating the Operations Dashboard Sequence Diagram using PlantUML (`uml/seq_dashboard.puml`).
- Specifying half-open date-range semantics (`[start_date, end_date)`), default `Today` boundaries, and invalid range validation.
- Defining historical occupancy denominator calculations using `RoomStatusHistory` and separating earned revenue from advance payments.
- Aligning the real-time room readiness summary with the five operational room states from Increment 9.

## 3. Main Design Decisions

- Access to `GET /api/dashboard/metrics` is restricted exclusively to authenticated `Hotel Manager` users via server-side FastAPI RBAC middleware (`403 Forbidden` for all other roles).
- Date filtering uses a half-open interval `[start_date, end_date)` defaulting to `[today, tomorrow)` (one operational day/night), rejecting zero-length or reversed ranges (`end_date <= start_date`) with `400 Bad Request`.
- Occupancy rate is calculated as `(Occupied Room-Nights / Available Active Room-Nights) * 100`, deriving historical availability from `Room` active flags and `RoomStatusHistory` so past `Out-of-Order` periods are accurately excluded.
- Expected arrivals count `Confirmed` reservations with `check_in_date` within `[start_date, end_date)`, while expected departures count active `CheckedIn` stays with `check_out_date` within `[start_date, end_date)`.
- Recognized revenue sums earned accommodation room-night charges and posted ancillary service charges accrued during `[start_date, end_date)` (`Folio`, `FolioCharge`, `Stay`), excluding unearned advance deposits for future stays.
- Real-time room readiness summarizes active physical rooms across all five states defined in Increment 9 (`Inspected`, `Clean`, `Dirty`, `Occupied`, `Out-of-Order`).

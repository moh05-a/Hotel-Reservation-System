# Increment 3 — AI-Assisted Design Record

**Version:** v0.3.0-design  
**Increment:** Availability Search  
**Requirements:** FR-AV-01–FR-AV-03, NFR-02

## 1. Design Task

Design the availability search feature for the Hotel Reservation System.

The system must search room types using check-in/check-out dates, guest count, and an optional room-type filter. It must consider Confirmed reservations and unexpired five-minute Pending holds when calculating available inventory.

## 2. AI Assistance

ChatGPT was used to assist with:

- Preparing the Availability Search Design document.
- Defining search inputs, validation rules, and inventory calculations.
- Explaining date overlap and check-out-exclusive rules.
- Creating the Availability Sequence Diagram using PlantUML.
- Preparing availability test scenarios and expected results.
- Identifying dependencies on reservations, Pending holds, and housekeeping.

## 3. Main Design Decisions

- Guests can search availability without creating an account.
- Reservations are made for room types rather than specific physical rooms.
- Each Room Type must support the requested guest count.
- Availability is checked for every night of the requested stay.
- Confirmed bookings and unexpired Pending holds consume room-type inventory.
- Expired and cancelled Pending holds do not reduce availability.
- Check-in dates are inclusive and check-out dates are exclusive.
- The minimum nightly availability determines availability for the complete stay.
- Searching does not create a reservation or Pending hold.
- Increment 5 performs an atomic inventory recheck before creating a Pending hold.

- Guest capacity filtering.
- Confirmed reservation overlaps.
- Adjacent and partially overlapping dates.
- Active, expired, and cancelled Pending holds.
- Availability across multiple nights.
- Fully booked room types.
